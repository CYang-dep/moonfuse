## 项目简介

MoonFuse 是面向 MoonBit 的 Linux FUSE 用户态文件系统协议库移植项目。它将 FUSE 的请求头、操作码、错误码、文件属性、目录项、回复帧、句柄和文件系统接口整理为 MoonBit 类型与函数，使开发者可以在不重复编写二进制协议处理代码的前提下，构建内存文件系统、归档文件系统、配置文件系统等不同实现。

当前 MoonBit 生态中，文件系统相关能力更多停留在普通文件读写或具体业务实现层，缺少一个位于“Linux 内核 FUSE 设备”和“用户态文件系统实现”之间的协议基础库。没有这一层时，开发者需要自行处理固定长度请求头、字节序、未知操作码、errno 语义、inode 与 file handle 的关联，既增加接入成本，也容易在截断输入和异常请求上出现边界错误。

MoonFuse 的定位不是另造一个文件系统，而是移植成熟生态中的通用协议能力。项目参考 libfuse 3 的公开协议与接口设计，并以 MoonBit 的包、trait、代数数据类型和接口快照方式重新组织代码。核心层与具体文件系统解耦，适合教学、测试、系统工具和 Linux 原生适配器等多种场景。

### 预期使用场景与三个示例

#### 示例一：只读内存文件系统

开发者用 MoonBit 构造一个固定 inode 树，将 `/docs/readme.txt`、`/metrics/runtime` 等节点映射为目录和文件。MoonFuse 负责 lookup、getattr、readdir 等请求的协议模型，示例实现只需要关注目录树和内容读取逻辑，适合教学、回归测试和协议调试。

#### 示例二：归档文件系统视图

将 ZIP、TAR 或其他归档格式的元数据转换为只读目录树。用户可以通过挂载点浏览归档内容，而不必先完整解压。归档解析器只负责产生名称、inode、大小和节点类型，MoonFuse 负责统一的用户态文件系统接口和错误语义。

#### 示例三：动态配置与运行时诊断文件系统

将程序配置、运行状态、统计指标和调试信息组织成虚拟目录，例如 `/config/current`、`/status/uptime` 和 `/debug/handles`。服务运行期间可以通过标准 Linux 工具读取这些信息，适用于服务运维、容器调试和本地开发环境。

## 核心功能范围

- FUSE 固定请求头解析：长度、操作码、请求唯一标识、inode、用户与进程信息。
- 操作码、errno、节点类型、文件属性和目录项的类型化表达。
- 小端字节读取、截断输入检查、越界偏移保护和未知操作码处理。
- 请求与回复帧模型，回复长度按 16 字节固定头和 payload 长度计算。
- `Filesystem` trait，覆盖 lookup、getattr、readdir 等通用入口。
- 请求分类、可重试操作判断、inode/file handle 关联模型。
- MoonBit 包接口文件、格式化、测试入口和 GitHub Actions 持续集成。

### 技术路径与关键理解

1. 先建立与 FUSE 公共协议一致的类型模型，避免把原始整数和字节数组直接暴露给上层。
2. 使用显式边界检查读取固定头，所有不足 40 字节或偏移越界的输入返回空值，不进行不安全读取。
3. 用 `Opcode?` 表示未知操作码，用结果类型承载后续文件系统实现的错误语义。
4. 将协议层、核心分派层和具体文件系统实现分离，保证归档、内存和动态配置等实现可以复用同一套核心。
5. 通过 MoonBit `moon check`、`moon test`、`moon info`、`moon fmt` 和 GitHub Actions 固化验证流程。

## 对标方案与量化指标

| 对标对象 | 适用语言/定位 | MoonFuse 的差异 |
|---|---|---|
| libfuse 3 | C/Linux FUSE 官方主流用户态库 | MoonFuse 不复制 C 实现，而是将协议核心以 MoonBit 类型和 trait 重新组织，便于 MoonBit 项目复用 |
| bazil.org/fuse | Go 用户态 FUSE 库 | MoonFuse 参考其协议分层思路，但不复用 Go 代码，面向 MoonBit 包和 native/Linux 目标 |
| 手写 FUSE 适配 | 任意语言 | MoonFuse 统一请求头、操作码、错误码和边界检查，降低重复协议代码与错误风险 |

项目采用以下可复核指标衡量实现质量：

- 协议覆盖：首版至少覆盖 30 个公开 FUSE 操作码及核心请求/回复模型。
- 安全边界：固定请求头少于 40 字节时返回空值；读取偏移越界时不触发异常访问。
- 回复一致性：回复长度始终等于 16 字节头加 payload 长度。
- 可复用性：至少提供 3 类不同领域的使用示例，且示例不修改协议核心。
- 工程验证：每次提交通过 `moon check`、`moon test`、`moon info` 和格式化检查；CI 在 Ubuntu 环境重复这些检查。
- 版本可维护性：公开接口通过 `.mbti` 文件记录，协议模型、核心分派和业务文件系统保持分层。

这里的指标是项目验收标准，不把尚未完成的 Linux 挂载适配宣称为已实现功能。当前版本已完成协议核心、解析器、类型模型、trait、句柄模型、质量文档和 CI；Linux native 设备适配、完整操作参数编解码和三个可运行文件系统示例属于后续迭代范围。

## 项目价值与生态意义

MoonFuse 的受众不是单一业务团队，而是所有希望在 MoonBit 中构建 Linux 用户态文件系统、虚拟文件树、归档视图、调试接口或系统工具的开发者。它补充的是跨项目可复用的协议基础设施，能够减少不同项目重复实现 FUSE 头解析、错误映射和句柄约定的成本。

项目的生态价值体现在三个方面：一是为 MoonBit 接入 Linux 系统能力提供可复用入口；二是把成熟 C/Go 生态中的文件系统协议经验转化为 MoonBit 类型安全接口；三是为后续内存文件系统、归档浏览器、容器诊断和开发工具提供共同底座。

## 移植或参考说明

项目参考 libfuse 3 的公开协议和接口文档，以及 bazil.org/fuse 的公开设计思路；代码由 MoonBit 独立重写，不复制上游源代码。移植范围包括协议头字段、操作码语义、错误码表达和用户态文件系统抽象；当前未支持完整 Linux `/dev/fuse` 设备读写、全部操作参数编解码、并发会话调度和跨平台挂载。

项目许可证、参考范围和差异说明见仓库中的 `NOTICE` 与 `docs/competition/duplicate-check.md`。项目不在本阶段发布到 MoonCakes，后续是否发布按比赛要求和版本稳定性另行处理。

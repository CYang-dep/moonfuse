# MoonFuse 开发计划

日期：2026-09-21

## 阶段

1. **工程基线**：模块、许可证、来源说明、CI、最小包结构。
2. **协议基础**：端序读写、FUSE header、操作码、错误回复和属性编码。
3. **请求模型**：请求类型、路径/inode/handle 模型、目录项和分派接口。
4. **文件系统接口**：lookup、属性、打开、读写、目录、创建删除、重命名、statfs。
5. **会话与后端**：mock device、请求循环、取消、Linux native FUSE device 边界。
6. **质量与示例**：单元/往返/故障测试，三个示例，文档和性能基线。
7. **交付准备**：moon info、moon fmt、moon test、CI、申报书、提交审计。

## 质量门槛

- 至少 2,000 行有实际功能的 MoonBit 核心代码，不包含生成物和重复占位。
- 至少 3 个可运行示例。
- 核心协议编解码往返测试、错误路径测试、mock 会话测试。
- Linux native 集成测试在 CI 中执行；Windows 开发机不宣称已运行 Linux FUSE 挂载测试。
- 至少 20 个有独立工程目的的有效提交，提交前逐项审计。
- README、许可证、NOTICE、CI 与最终代码保持一致。

## 明确不做

- 不复制 libfuse、bazil.org/fuse 或其他上游源码。
- 不把普通文件系统 API、文件监视、归档解析冒充 FUSE 实现。
- 不在未验证 Linux 权限/设备环境时声称真实挂载测试通过。
- 不发布到 MoonCakes，除非用户另行明确要求。
